# 首页 VP 在线人数

首页选赛框右上角显示绿点和「现在有 X 人正在 VP 中」。统计全站正在计时的 VP 页面，暂停、预约等待、加载失败、结束后停止发送心跳。

每个标签页生成随机 UUID，保存在 sessionStorage，刷新后复用。匿名 ID 和比赛 ID 仅在 POST 请求体中发送，不加入页面或接口 URL；不发送队名、单位、IP 或手动提交。人数按在线标签页近似统计，不是登录用户去重人数。

## EdgeOne Makers 部署

1. 使用包含 `edge-functions/api/vp-presence.ts` 的完整 Git 仓库部署，而非只上传 `dist/`。
2. 构建命令 `pnpm build`，静态输出目录 `dist`，函数目录为根目录 `edge-functions`。
3. 项目需要启用 Blob。函数通过 `@edgeone/pages-blob` 的 `getStore('vp-presence')` 使用项目内自动认证，不需要 KV，也不需要在前端配置 Token。
4. 发布后访问 `/api/vp-presence`，应返回 JSON：`{"count":0,"updatedAt":...}`。如果返回 HTML，请检查函数是否已随仓库部署及路径重写规则；503 表示 Blob 或函数配置未就绪。前端将显示「在线人数暂不可用」。

若平台没有自动提供 Blob 凭证，需要在函数运行环境配置平台提供的 `PAGES_BLOB_DEPLOY_CREDENTIAL`；不要放进 `VITE_*` 变量或浏览器代码。实际部署需在对应 Makers 项目确认 Blob 可用。

## 心跳、统计和清理

- 运行中的 VP 每 30 秒 POST `/api/vp-presence`，请求体为 `{sessionId, contestId}`；首页每 30 秒 GET 同一路径，仅返回在线会话数和统计时间。
- 服务器为心跳生成时间戳，统计最近 90 秒内的会话，重复心跳只计一次。关闭或暂停页面后最多约 90 秒移出统计。
- Blob 使用 `heartbeats/{分钟桶}/{服务器时间戳}-{sessionId}.json` 独立对象，避免访客并发更新一个计数文件而丢失增量。
- 统计只列举最近 90 秒涉及的时间桶，使用 `consistency: 'strong'`；不逐个下载心跳文件，不缓存统计响应。
- 接口请求顺带清理过期时间桶，每次最多删除 128 个对象。没有请求时，旧对象保留到下一次访问时清理，但不会被计入人数。不要在这个 Store 里存业务文件。
- 全站匿名公开接口无法阻止脚本模拟多个会话；如果出现滥用，可在 EdgeOne 配置此路径的请求限频。不要把此数字当成精确真人统计。

## 本地验证

`pnpm dev` 自动提供同样的接口，使用进程内存跨本地标签页共享；无需配置云端凭证。开发服务重启会清空本地人数，线上函数始终使用 Blob。

`pnpm test` 包含并发会话去重、心跳到期、旧对象清理、无敏感 ID 响应、输入限制及存储失败的测试。
